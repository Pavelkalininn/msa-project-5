# Обоснование выбора метрик для Spring Batch приложения

## Выбранные метрики

1. **`spring_batch_job_duration_seconds`**
2. **`spring_batch_job_execution_count`**
3. **`spring_batch_step_execution_count`**
4. **`spring_batch_item_read_count`**

## Обоснование по методологии USE (Utilization, Saturation, Errors)

### 1. `spring_batch_job_execution_count` - Utilization
** Показывает использование приложения - сколько раз job был запущен. Высокое значение указывает на активную эксплуатацию системы.

### 2. `spring_batch_job_duration_seconds` - Saturation
** Отображает загрузку системы - время выполнения job. Увеличение длительности свидетельствует о насыщении ресурсов или проблемах с производительностью.

### 3. `spring_batch_step_execution_count` - Errors (косвенно)
** Помогает выявить ошибки на уровне шагов. Несоответствие между количеством запусков job и шагов может указывать на проблемы в выполнении.

### 4. `spring_batch_item_read_count` - Utilization
** Показывает объем обрабатываемых данных. Резкие изменения могут сигнализировать о проблемах с источниками данных или изменении нагрузки.

## Обоснование по четырем золотым сигналам

### 1. `spring_batch_job_duration_seconds` - Latency
** Измеряет время выполнения batch job - ключевой показатель задержки обработки данных.

### 2. `spring_batch_job_execution_count` - Traffic
** Отображает объем запросов на выполнение job - показатель нагрузки на систему.

### 3. `spring_batch_item_read_count` - Errors (качество данных)
** Неожиданные изменения в количестве читаемых элементов могут указывать на проблемы с источниками данных или их качеством.

### 4. `spring_batch_step_execution_count` - Saturation
** Показывает загрузку системы на уровне отдельных шагов обработки.

## Обоснование по методологии RED (Rate, Errors, Duration)

### 1. `spring_batch_job_execution_count` - Rate
** Скорость выполнения job - сколько job выполняется в единицу времени.

### 2. `spring_batch_item_read_count` - Errors (качество)
** Помогает выявить ошибки в процессе чтения данных через аномалии в количестве обрабатываемых элементов.

### 3. `spring_batch_job_duration_seconds` - Duration
** Длительность выполнения job - основной показатель производительности.

### 4. `spring_batch_step_execution_count` - Rate (детализация)
** Детализированная скорость выполнения на уровне шагов.

## Заключение

Выбранные метрики обеспечивают полное покрытие мониторинга Spring Batch приложения через призму трех современных методологий мониторинга. Они позволяют эффективно отслеживать производительность, обнаруживать аномалии и оптимизировать работу системы обработки данных.


# Обоснование выбора способа отправки логов и конфигурации оповещений:

Для отправки оповещений была выбрана рассылка через телеграм-бот, как наиболее оперативный вариант доставки уведомлений сотрудникам
