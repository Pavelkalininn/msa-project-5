
Обоснование:
Наиболее удобным решением в данной ситуации является Apache Airflow,
т.к. есть возможность мониторинга из коробки и достаточно простая логика
построения пайпов с возможностью масштабирования.

Выбранное решение может интегрироваться с другими системами посредством операторов модулей(пакетов)
BigQueryOperator -> BigQuery
RedshiftOperator -> RedShift
пакет apache-airflow-providers-apache-kafka -> Kafka
пакет Spark provider -> Apache Spark
Пакеты являются готовыми модулям, упрощающими интеграцию.

Решение поддерживает ветвление, условные операторы и event-triggers. Есть возможность отображения последовательности ветвления в UI интерфейсе и запуске вручную.
Возможно использования из коробки fallback-logic, retry и отправку email уведомлений.
В облачной среде решение разворачивается в кластере kubernetes.

Во всех популярных облачных средах есть преднастроенные сервисы запуска Airflow.

| | SpringBatch | ApacheAirflow | K8s Job | Spark |
| --- | --- | --- | --- | --- |
| Наличие конфигурации CRON-расписания | + |  + | +  | + | 	
| Сложность реализации логики по обработке данных | средняя | низкая | высокая | высокая|	
| Ресурсоемкость решения (количество потребляемых ресурсов) | средняя | низкая | высокая | средняя |

| Удобство интеграции с системами логирования и мониторинга| низкое | высокое | высокое | низкое |
